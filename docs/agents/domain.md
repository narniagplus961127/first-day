# Domain documentation

Use one root GLOSSARY.md and docs/adr/ directory.

Before exploring an area, read the glossary and relevant ADRs
when they exist. Proceed when they are absent.

Create glossary entries as terminology is settled.
Keep implementation details outside the glossary.
Use canonical glossary terms throughout specifications and code.

Record ADRs for consequential decisions involving real trade-offs.
Surface conflicts with existing ADRs explicitly.
