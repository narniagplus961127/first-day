# Markdown language admission

Initial upload and explicit replacement share the same server validator before persistence and before any provider request. Files still require one .md UTF-8 document, at most 102400 bytes, usable letters/numbers and no forbidden control characters. Rejected language returns HTTP 400 with guidance to use English instructions while keeping names/code unchanged; a rejected replacement does not create a candidate or change the active version.

The practical dependency-free policy examines prose and headings outside fenced/indented/inline code, removes HTML tags and URL/link destinations, and leaves original stored Markdown untouched. At least 60% of prose letters must use the Latin script. Short notes with fewer than eight Latin word tokens remain admissible so technical marker-only headings and brief setup/code guides work. Longer prose needs at least two distinct words from a small English function-word/instruction vocabulary. Unicode Latin names and punctuation are allowed, and code literals/comments may use any script. Code-only text has no natural-language evidence and is allowed under this heuristic.

This is an admission heuristic, not a statistical language detector or a guarantee that all accepted text is English. Short Latin-script text, borrowed words and mixed-language prose may be ambiguous; predominantly non-Latin documents and substantive Latin prose without English cues are rejected. An unusual valid English document may need a short English explanation. The rule does not impose ASCII-only content, full sentences, an external dependency, a model call or a provider charge. Broader multilingual ingestion requires an explicit future policy rather than silently treating this heuristic as language classification.
