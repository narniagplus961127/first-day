# Lumen Designer onboarding

This is a fictional Lumen exercise, not the FirstDay repository or instructions for a real employer. Workspace names, paths and review conventions below describe an imagined practice file. Use invented content only. Nothing here requires access to a real design account, sending messages or purchasing assets.

## Before you start: workspace and foundations

Read this guide before making an exercise copy. The fictional workspace is Lumen Sandbox. Its shared design kit is Lumen Foundations v1. Use the space.4 spacing token, which equals 16 px, for the welcome-flow exercise.

In the imagined library panel, locate Lumen Foundations v1 and inspect its component examples and token descriptions. The brand color token is color.brand.500; use the token reference rather than typing a replacement color. The spacing reference is space.4 = 16 px. Keep both references in your practice notes so a reviewer can identify the intended values.

## Day 1: open a practice workspace

In Lumen Sandbox, duplicate the Practice / Welcome flow frame into Sandbox / welcome-practice. Work in that duplicate and leave the shared source frame unchanged. The exercise name can describe your own fictional experiment; keep its destination under Sandbox / <exercise-name>. No actual shared file needs to be changed to follow this written exercise.

## Day 1: review components and tokens

Use Lumen Foundations v1 and the space.4 spacing token (16 px). Component names follow Category/Name/State, for example Button/Continue/Default, Button/Continue/Focus and Field/Name/Error. Reuse a library component when its meaning fits the screen, then note its name and token references in the practice frame. Use color.brand.500 for the intended brand treatment and space.4 for the welcome card's internal gap. Document default, focus and error states rather than describing only the default appearance.

## Day 1: inspect the welcome flow

Trace this fictional sequence: open the welcome card, enter an invented display label such as Demo Learner A, choose Continue, then inspect the confirmation state. Compare the default card with its focus and error variants. An empty display label should show the sample error message Enter a practice label; a valid invented label proceeds to confirmation. Write down the action and expected state for each step. Do not collect a real learner's name or other personal information.

## Week 1: check accessibility

Use this exercise checklist: inspect text contrast against the chosen background, make keyboard focus visible on each interactive element and use descriptive labels for fields and actions. Follow the intended focus order from the display-label field to Continue and then confirmation. An error must be communicated with text, not color alone. Record a concrete observation for each check; this design exercise does not certify a shipped interface's accessibility.

## Week 1: prepare a small change and feedback

Change only the fictional welcome card's spacing in your exercise copy to use space.4 consistently. Keep component names, default/focus/error states and the imagined flow behavior clear. Compare the original and proposed frames and repeat the accessibility checklist.

Record feedback as Observation / Impact / Proposal. For example: Observation: the welcome card uses inconsistent internal gaps. Impact: the relationship between the label and action is harder to scan. Proposal: use space.4 (16 px) consistently and check the focus state again. Keep the feedback as a practice note; no real review request or message is required.

## Week 1: write a handoff note

A practice handoff includes the frame link or its written fictional frame path, token/component references, interaction states and open questions. For this exercise, identify Sandbox / welcome-practice, Lumen Foundations v1, space.4 and color.brand.500; list the relevant Category/Name/State component names. Explain the default, focus and error behavior plus the confirmation action. Finish with any unresolved question and its effect on the design. Save the note alongside the imaginary practice frame without publishing or sending it.
